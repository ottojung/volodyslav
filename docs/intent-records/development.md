# Development branches

$id-wipdocslead
date: 2026/09/07
source: @ottojung
kind: requirement

Work-in-progress integration branches may intentionally contain specifications for implementation that is still being developed on that branch.

Documentation/code consistency is required before a branch is treated as release-ready or promoted into a release-ready branch. During active integration work, a specification may lead the implementation when both belong to the same living in-progress design. This exception does not permit documentation of discarded designs, superseded implementations, development-process narration, or unrelated future ideas.

An explicitly work-in-progress integration branch is therefore allowed to temporarily contain normative specifications whose implementation has not landed yet, provided the branch is being used to integrate that implementation before release.
